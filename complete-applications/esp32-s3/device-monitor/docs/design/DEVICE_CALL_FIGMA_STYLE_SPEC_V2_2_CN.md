# 设备呼叫 Figma 视觉规范 v2.2

状态：视觉评审稿，业务状态机继续以
`DEVICE_CALL_BUSINESS_AND_WIREFRAME_V2_CN.md` 为依据；页面表现以本规范和
Figma 原节点为依据。

## 1. 纠正结论

上一套 `device_call_v2_1` 图片没有读取 Figma 的真实节点参数，出现了大字
号、过度留白、手机式页面和不属于本项目的组件语言，已经作废。

本轮直接读取 Figma 页面 `12:2` 下的呼叫、联系人、来电、通话、键盘和扫码
节点，并使用确定性 HTML/CSS 在 320 x 240 画布上复现。图像模型不再负责
排版和文字。

## 3. 业务与硬件特色结合

- 呼叫首页保留 Figma 原有的双入口结构：`添加联系人`、`联系人列表`。
- 右侧显示本机设备二维码，发挥屏幕能力，供另一台设备扫码。
- 添加联系人页以摄像头扫码为第一操作，手动输入 Device ID 为备用操作。
- 二维码只编码公开的 12 位 `device_id` 原文，下方显示同一设备 ID，不使用 JSON，不显示或保存设备密钥、配对 Key 和 token；点击首页二维码全屏展示，再次点击退出。
- 扫码页面使用 320 x 240 全屏实时预览，不放标题栏；固定 UI 只有四个绿色
  取景角标。
- 扫码成功后先释放摄像头，再显示符合 Figma 弹层语言的确认框。
- 来电使用 Figma 现有轻弹层覆盖呼叫首页，不跳成手机式全屏来电页。
- 通话控制沿用 Figma 的紧凑行布局，并按设备音频通话语义改为麦克风、扬声
  器、麦克风开关和挂断。

## 5. 实现门禁

1. 固件页面只能从本规范、Figma 原节点和 v2.2 图片集取视觉参数。
2. `device_call_v2_1` 不能作为任何尺寸、颜色或布局依据。
3. 每个页面必须通过 320 x 240 边界检查和文字裁切检查。
4. 中文如果按项目策略导出 PNG，应按本规范的字号、颜色和容器坐标导出，
   不能由生成模型重写文字形状。
5. 摄像头画面是运行时内容，不做成固定背景图片；只实现取景角标和退出逻辑。
