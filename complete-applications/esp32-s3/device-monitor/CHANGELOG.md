# 变更记录

## 1.9.6 - 2026-08-26

比较基线：`v1.9.5`（`45db394cae399967a9c3b882d595cdecb80321be`）。TiRTC SDK、分区表
和 ESP-IDF 版本保持不变。

### 呼叫体验

- 拆分设备呼叫的音频资源准备和 RTC 就绪等待。首次完整烧录后发起呼叫时，设备可以在后台
  等待正式上线和 TiRTC 监听，不让界面长时间失去响应。
- 正式在线等待上限为 30 秒；RTC 就绪等待上限为 50 秒，准备动作每 500 ms 推进一次；
  呼叫响铃超时保持 45 秒。
- 发起呼叫前，呼叫请求最多等待 12 秒，让已经运行的房间恢复、联系人刷新或联系人变更任务
  结束；超时仍忙则明确拒绝本次呼叫。呼叫活跃后不再启动新的房间恢复或联系人刷新，结束后恢复，
  减少 HTTPS 与 RTC 同时抢占网络和内存资源。
- 呼叫快照补齐主叫/被叫角色、对端设备、`last_error` 和状态消息。页面区分准备、等待接听、
  建立连接和通话中，并短暂显示对方取消、拒接、挂断、超时、断开或失败结果。

### 触摸交互与设置

- 设备联系人和微信联系人名称改为输入框与屏幕键盘编辑；键盘确认键由 `Join` 改为 `OK`，
  不再局限于固定备注列表。
- 设备查看、设备呼叫、微信 VoIP 和小钛设置页的音量 `+/-` 在按下时立即生效，并扩大触摸
  区域；静音仍需完整点击确认。
- 删除设置页中的 TiRTC 测试、手动启动 RTC 和 sender audio test 入口。RTC 继续由应用
  生命周期自动准备和释放。

### 服务入口与证据

- H5 入口保持 `https://demo-open.tange-ai.com/`；已有 HTTPS/MQTTS、证书链和 hostname
  校验契约保持不变。
- 开发来源锁定 annotated Tag `v1.9.6`、commit
  `cdb5d7bec9c955227a1259281686e30377332fb3`。公开构建输入提交为
  `ccae5fd495109244a679c5ffe1e17f98d6589f52`，repository tree 和项目 tree 分别为
  `a0fde688fb4dbd2b7803fde487046f4de6cccd0d`、`d5d5a8fb3f818106b77eeccc2599482943260be9`。
- 唯一正式干净构建使用 ESP-IDF `5.5.4`、GCC `14.2.0_20260121` 并禁用 ccache，完成
  `1767/1767`，无编译 warning、error 或 ICE。app 为 `7,611,216` bytes，分区剩余
  `187,568` bytes（`2.41%`），容量余量仍是发布风险。
- 本次正式构建不等于烧录、冷启动呼叫、联系人键盘、音量触摸或长稳验证。Web IPC 和设备
  互呼仍可能听到轻微“沙沙电流声”，根因尚未证实，本版本不宣称已经修复。

## 1.9.5 - 2026-08-25

比较基线：`v1.9.0`（`a64422b0efdebe6c303370effafd52bbf51593d1`）。设备主动呼叫微信
联系人继续使用体验版 `wx_version_type=2`。

### 用户可见变化

- 网络测试页现在分别显示平均时延、抖动和丢包率。测试发送 20 次探测，结果以结构化字段
  从网络层传到应用快照、UI 和串口诊断，不再依赖一段汇总文字反向解析。
- 普通设备来电增加本地铃声；接听、拒接、对端取消、挂断或身份重置会按状态停止铃声。
  铃声实时生成，不增加大块 WAV 资源；任务栈和 PCM 缓冲使用 PSRAM。
- 设备呼叫的接听、挂断和失败状态继续收口；新引入路径中的内存不足会保留真实失败语义，
  不改写成成功结果。

### 设备互呼音频

- Web IPC、设备互呼和微信 VoIP 的设备上行线格式统一核对为
  `8 kHz / 16 bit / mono / G.711 A-law / 20 ms / 160 bytes`。设备互呼显式 CALL gate
  使用同一 A-law 编码契约，避免路径切换时回退成 PCM。
- 设备互呼播放配置增加按缓冲水位工作的有界速率微调：每个 20 ms 播放周期最多调整
  4 个 16 kHz 采样帧，约为 `1.25%`。此策略只用于 Device Call，不改变 Web IPC、微信
  VoIP 或小钛的播放配置。
- 设备互呼 AEC 改用全双工高性能线性模式，AEC 工作区申请在 PSRAM；AEC 后增加 100 Hz
  高通，并采用更保守的通话 AGC 噪声底线。噪声门保持关闭，避免切掉轻声起音和词尾。
- G.711 A-law 连续流编码保留跨包 FIR 状态，并在连接代际变化时重置；TiRTC 与微信 VoIP
  使用同一套连续流处理。

### 网络与 SDK 安全

- 服务发现入口改为 HTTPS，设备服务只接受 `HTTPS`，MQTT 只接受 `MQTTS`。发现结果出现
  `http://` 或 `mqtt://` 时会被拒绝并报错，不覆盖安全兜底。
- 应用 HTTP 客户端校验证书链和主机名并禁用自动重定向；临时绑定 MQTT、正式设备 MQTT
  和 TiRTC 配置入口在创建连接前再次检查安全协议。
- TiRTC SDK 以 `db7290f` 为功能基础，增加 `13e34c3` 的 HTTPS 服务端认证修复。SDK 自有
  HTTP 客户端强制 `MBEDTLS_SSL_VERIFY_REQUIRED`，挂接 ESP-IDF 证书包并校验 hostname。
- 公开 `libTiRTC.a` 大小为 `2,125,366` bytes，SHA-256 为
  `83556eeee0c6cae45961899a4c5d1255a5d0d33f8e636104a946ce41ff3e20d7`。归档执行
  `--strip-debug` 以移除内部调试路径；BuildInfo 保持 `v2.3.0-db7290f`，成员、符号和运行代码
  契约不变。

### 证据与边界

- 相同功能代码在版本号收口前完成过双板设备互呼验证：约 14 秒、每端约 690 个媒体包，
  `media=2`、`flags=0`、`160 bytes / 20 ms`，发送失败、丢弃和下溢计数为 0。
- G.711 A-law 完成 20,000 次编解码自检，`checksum=415d3715`、`heap_ok=1`。这些结果说明
  当前线格式和编解码器自检未见异常，不等同于最终 `1.9.5` Release 固件已经完成真机回归。
- 统一公开代码快照为 `c27914eafab6f700cecf196da48987200cd54d37`。正式构建使用的隔离
  候选与该提交的 repository tree `b0b93ddc0c82ae65130ae6dab17ff6ee6dbfc86a`、项目 tree
  `9fa7f85ce92a0e5fcd27c4a36fabe02609191391` 完全一致；构建使用 ESP-IDF `5.5.4`、
  禁用 ccache 的全新目录，本次完成 `1767/1767`，app 为
  `7,608,608` bytes、
  SHA-256 `51a7599942f06556e33ef4820499885d6213ff15fce0f3ed2f11e38e44146503`、分区剩余 `190,176` bytes
  （`2.44%`）。
- Web IPC 和设备互呼的当前人耳试听仍可感知轻微“沙沙电流声”。现有证据缩小了排查范围，
  但底噪根因尚未证实；本版本不宣称该问题已经解决。
- 正式构建确认 app 分区余量为 `190,176` bytes（`2.44%`），不能复用 `1.9.0` 的固件、
  大小或哈希。
- TLS 修复已核对到源码、对象、归档、APP 链接和构建。目标板上的有效证书成功、错误证书或
  错误主机名失败，以及绑定、MQTT 和各 RTC 业务回归仍需单独验证。

## 1.9.0 - 2026-08-24

比较基线：`v1.8.0`（`8211e3bec7a40beff5cfe81dbf9cb8468016e786`）。`1.8.1` 的
微信主动呼叫体验版配置继续保留。

### SDK 与系统配置

- TiRTC SDK 升级到官方 `2.3.0 mini`，头文件、TGTRP/统计接口、静态库和版本说明来自
  同一交付包。
- `libTiRTC.a` 大小为 `8,081,578` bytes，SHA-256 为
  `43b06d1da421c7d24cc7fdb1385d600ecdffbfd2d3801f7faf0c540fb5cdbaa2`。
- `sdkconfig.defaults` 收口 FreeRTOS 1 kHz、main task 16 KiB、96 KiB internal RAM reserve、
  外部任务栈，以及 NVS cache、mbedTLS、MQTT outbox 的 PSRAM 策略。
- Watchdog panic 保持开启，错误信息在发布构建中可见。

### 音频与生命周期

- 完善 S3 音频采集、播放和 AEC 链路，增加自适应抖动缓冲、缺帧补偿和媒体完整性统计。
- 增加 checksum failure、missing、duplicate、reordered 等计数，帮助区分网络抖动、队列
  背压、媒体格式和音频外设问题。
- 收口 TiRTC 连接、任务栈、断开与资源释放策略，Device Call、小钛、Web IPC 和微信 VoIP
  继续由应用层统一仲裁。
- RTC 产品能力固定为双向音频；摄像头只用于联系人二维码扫描，不作为 RTC 视频源。

### 诊断与发布

- 新增默认开启的串口 AT 诊断 CLI，可查看 Wi-Fi、网络探测、Socket、RTC、媒体、音频路径、
  AEC、呼叫和内存状态；量产不需要时可在 Kconfig 关闭。
- 来源 Tag `v1.9.0` 已完成开发侧构建。统一公开代码快照
  `d76e6e3b7f02f112b55ed917daa17f530b3c7a6b` 也已在全新目录完成 ESP-IDF `5.5.4`、
  禁用 ccache 的正式干净构建，并生成唯一一套 Release 资产。
- app 分区余量约为 `3%`，属于明确容量风险；正式大小和 SHA-256 以 Release manifest 为准。
- 构建、烧录、联网、业务功能、音频效果和长稳继续分开记录，不用构建结果替代目标板证据。

## 1.8.0 - 2026-07-31

比较基线：`v1.7.6`（`04dfca5345f3b3ae6b0afa94e8a4d1d49986d214`）。

### 新增与改进

- 小钛新增联系人状态查询，以及设备联系人、微信联系人呼叫动作。
- 设备联系人支持音频和视频呼叫；微信联系人当前支持语音呼叫。
- 设备呼叫补齐 `call_type` 校验与传播，共享 RTC 命令按设备呼叫和微信会话正确分流。
- 微信联系人兼容 `data.contacts`、`data.list` 及常见字段别名。
- 微信联系人支持异步更新备注，使用 NVS schema v2 保存缓存，并在更新后刷新服务端权威列表。
- 联系人界面新增 9 个预设备注：妈妈、爸爸、爷爷、奶奶、外公、外婆、哥哥、姐姐、朋友。
- AI 品牌名称统一为“小钛”和“小钛设置”。
- 新增 43 组、每组 10/12/16 三种尺寸，共 129 张界面文本资源。

### 兼容性

- TiRTC SDK 保持 `2.2.0`，本版本未替换 SDK 静态库。
- ESP-IDF 保持 `5.5.4`，Flash、分区表和硬件目标保持不变。
