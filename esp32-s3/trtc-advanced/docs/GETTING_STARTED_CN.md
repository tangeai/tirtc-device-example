# 从连接 Wi-Fi 到体验功能

这份文档面向第一次拿到设备的人，目标是把设备从开机、联网、查看状态，一路带到 Web 端 IPC 监看、TiRTC 通话、微信通话和 AI 对讲体验。

如果要按普通体验者的真实操作顺序演示，先看 [完整体验流程：从开机到 IPC、微信、AI 和 OTA](USER_EXPERIENCE_FLOW_CN.md)。

## 1. 准备设备

1. 准备一块已烧录本工程固件的 ESP32-S3 设备。
2. 给设备供电，等待屏幕进入主页。
3. 确认触摸屏可以点击和左右滑动。主页第一页通常包含查看、呼叫、微信，向左滑动后可以看到 AI 对讲和设置。
4. 准备一个 2.4 GHz Wi-Fi。ESP32-S3 设备侧通常建议使用 2.4 GHz 网络，密码不少于 8 位。

如果设备还没有烧录固件，先看 [烧录与 OTA 快速教程](FLASH_AND_OTA_CN.md)。本示例面向 `esp32s3_tirtc_monitor` 开发板，需要 16 MB Flash、PSRAM、320 x 240 触摸屏、音频和摄像头等板级外设。

同款开发板就是嘉立创/立创开发板的“立创·实战派 ESP32-S3 开发板”，型号可按 `LCKFB-SZPI-ESP32-S3-VA` 查找。购买入口可参考立创开发板项目页 <https://lckfb.com/project/detail/lckfb-esp32-s3-va?param=baseInfo> 或立创商城 <https://item.szlcsc.com/43285221.html>。普通 ESP32-S3 DevKit 可以用于学习 ESP32-S3，但不能直接完整体验本示例的屏幕、触摸、音频和摄像头功能。

如果固件中已经写入默认 Wi-Fi，设备会在启动后自动连接；如果未连接，按下面步骤手动连接。

## 2. 连接 Wi-Fi

1. 在主页向左滑动到第二页，点击设置。
2. 进入系统设置页后，点击 Wi-Fi 设置。
3. 页面会显示当前连接状态和扫描结果。点击右上角刷新可重新扫描附近 Wi-Fi。
4. 在列表中选择要连接的 SSID。
5. 进入连接页面后输入 Wi-Fi 密码。
6. 点击连接，等待状态变为已连接并保存。
7. 返回主页，顶部 Wi-Fi 状态会同步更新。

连接成功后，SSID 和密码会保存在设备 NVS 中。下次开机时设备会优先使用保存过的 Wi-Fi 自动连接，不需要每次重新输入。

## 3. 用 6 位验证码完成设备绑定

后续 Web IPC、设备呼叫、微信通话和 AI 对讲都会依赖同一套设备身份。当前公开体验流程不需要用户手动填写设备 ID 或设备密钥，而是走设备绑定服务：

1. 设备连接 Wi-Fi，并完成时间同步。
2. 如果本地没有设备身份，主页会自动弹出设备绑定窗口。
3. 设备向绑定服务上报 `mac/chip_uid`，拿到 6 位绑定码和临时 token。
4. 用户在绑定网页、业务后台或配套小程序里输入这 6 位验证码。
5. 业务服务确认后，通过绑定 MQTT 下发 `device_id/device_key`。
6. 设备自动保存凭证到 NVS，并启动在线、RTC、微信和 AI 对讲所需的业务链路。

设备屏幕上的绑定窗口会显示：

- 6 位绑定码。
- 绑定服务入口二维码。
- 绑定服务地址，默认来自 `APP_CONFIG_DEVICE_BINDING_API_BASE`，当前为 `http://mqtt-demo.tange-ai.com`。

如果设备还没有联网，主页会先提示“请先连接 WiFi”。点击提示里的设置 Wi-Fi，连上 2.4 GHz Wi-Fi 后回到主页，设备会继续获取绑定码。

### 3.1 绑定失败时怎么处理

1. 确认 Wi-Fi 已连接，并且设备可以访问公网。
2. 确认绑定网页或后台使用的是同一个环境的业务服务。
3. 绑定码有有效期，超时后点击绑定窗口里的刷新，重新获取验证码。
4. 如果设备已经绑定过旧账号或旧环境，进入设置 -> TiRTC 配置，点击重置绑定，设备会清空本地身份并重新进入 6 位验证码绑定流程。
5. 不要把设备密钥放进截图、公开文档或公开仓库；普通体验者不需要看到设备密钥。

## 4. 查看设备状态

1. 回到主页，点击查看。
2. 确认 Wi-Fi 已连接、IP 已获取。
3. 确认页面展示的是绑定后保存的 `device_id`。
4. 查看页二维码用于 Web IPC 或调试页面导入当前设备连接信息。
5. 如果页面显示未连接，请先回到设置里的 Wi-Fi 设置页重新连接。

查看页适合用来确认设备是否已经具备后续 TiRTC、微信通话和 AI 对讲体验所需的基础网络条件。

## 5. 在 Web 端体验 IPC 功能

IPC/设备监控功能推荐在 Web 端体验。Web 端正式体验域名为：

<https://demo-tirtc.tange365.com/>

体验前先确认设备侧已经完成以下状态：

1. 设备已经连接 Wi-Fi，并能在查看页看到 IP。
2. 设备已经通过 6 位验证码完成绑定。
3. 设备进入主页的查看页面，让设备侧 RTC 服务处于可连接状态。
4. 查看页会展示当前设备 ID 和连接二维码，可用于 Web 端连接。

Web 端体验步骤：

1. 在电脑或手机浏览器打开 <https://demo-tirtc.tange365.com/>。
2. 进入 IPC/设备监控相关入口。
3. 按页面提示选择或导入已绑定设备；如页面提供扫码能力，可以扫描设备查看页上的二维码。
4. 点击连接或开始查看。
5. 连接成功后，在 Web 端查看设备侧画面和音频状态。
6. 如果 Web 页面提供音量或开门等控制项，可以直接在 Web 端操作，设备侧会收到对应控制命令。
7. 体验结束后，在 Web 端断开连接，再从设备侧返回主页。

如果 Web 端连接失败，先检查三个点：设备是否还连着 Wi-Fi，设备是否已经绑定，设备是否停留在查看页面。

## 6. 体验 TiRTC 设备呼叫

TiRTC 设备呼叫用于验证设备到设备的实时音视频链路。

1. 确认设备已经连接 Wi-Fi。
2. 在主页点击呼叫。
3. 如需添加联系人，可进入添加联系人，通过二维码或联系人信息完成绑定。
4. 进入联系人列表，选择目标设备并发起呼叫。
5. 对端接听后进入通话页。
6. 通话中可以调节接收音量和发送音量。
7. 发送音量调到 0 时，本机麦克风上行会静音，不再继续发送音频帧。
8. 点击挂断返回呼叫页，返回主页时会释放呼叫相关 RTC 和音频资源。

如果点击呼叫时提示请先连接 Wi-Fi，说明当前网络还没有进入可用状态，需要先回到 Wi-Fi 设置页处理网络。

## 7. 体验微信通话

微信通话依赖业务服务器、微信小程序、微信联系人绑定和 VoIP 授权缓存。体验前需要确认服务端已配置对应设备身份，并且设备侧和小程序侧使用同一套业务服务。

本示例沿用 TiRTC 微信 VoIP example 的小程序体验链路：

- 设备侧默认绑定/VoIP HTTP 服务：`http://mqtt-demo.tange-ai.com`
- 设备侧默认 thing-connect MQTT 服务：`mqtts://mqtt-demo.tange-ai.com:8883/mqtt`
- 绑定流程写入 `device_id` / `device_key` 后，设备在线服务统一维护 MQTT 连接，微信 VoIP 只注册自己的业务消息监听。
- 示例小程序 AppID：`wx27d4b2d7eb37eb58`
- 示例微信 IoT VoIP ModelID：`HRHY_vJ9mHI2KQhd6yvj9Q`

如果使用自己的微信小程序和业务服务器，请同步替换小程序 AppID、ModelID、服务端配置，以及设备侧 `APP_CONFIG_DEVICE_BINDING_API_BASE` / `APP_CONFIG_DEVICE_BINDING_MQTT_URI`。微信端打开入口建议使用“体验版小程序二维码”：由项目维护者在微信公众平台生成后发给体验者，用微信直接扫码进入。

这里要区分两个二维码：

1. 小程序二维码：用于打开微信小程序体验入口。
2. 设备 ID 二维码：只包含 12 位 `device_id`，用于小程序里的“扫码添加设备”。它可以由设备查看页展示，也可以把 12 位设备 ID 用二维码工具生成。

不要把 `mp.weixin.qq.com/wxamp/home/guide?...token=...` 这类后台管理地址分发给体验者；它不是小程序入口，token 也可能失效。

微信侧发起呼叫步骤：

1. 确认设备已经连接 Wi-Fi，并且已通过 6 位验证码完成绑定。
2. 在设备主页点击微信，让设备侧注册微信 VoIP 业务监听并等待 MQTT 通知。
3. 用微信扫描项目维护者提供的体验版小程序二维码，打开 TiRTC 微信 VoIP 示例小程序。
4. 在小程序里点击添加设备，选择扫码添加或手动输入设备 ID。
5. 如果扫码添加，扫描设备查看页上的设备 ID 二维码，或扫描只包含 12 位 `device_id` 的二维码。
6. 小程序添加设备后会调用 `/tirtc/voip/user/bind`，服务端保存 `device_id + openid` 的联系人关系。
7. 在小程序里点击授权呼叫，授权流程会先获取 `sn_ticket`，再调用 `wx.requestDeviceVoIP`，授权成功后上报 `/tirtc/voip/user/report-auth`。
8. 授权完成后点击发起呼叫，小程序通过微信 VoIP 插件呼叫设备。
9. 业务服务器收到微信侧事件后，通过设备 MQTT 通知下发 `call_incoming`，设备解析其中的 `peer_id` 和 `token` 后进入 TiRTC WHIP 通话。
10. 通话中可以调节接收音量和发送音量，挂断后回到微信页面。

设备侧主动呼叫微信步骤：

1. 先按上面的微信侧流程完成设备添加和 VoIP 授权。
2. 设备在线时会从服务端收到授权缓存，或重新进入微信页面后主动拉取授权列表。
3. 在设备微信页面选择已授权联系人，发起微信呼叫。
4. 微信侧响铃并接听后，设备进入通话状态。

如果页面提示联系人不存在、呼叫接口不可用或请先连接 Wi-Fi，需要分别检查联系人绑定、业务服务连接和 Wi-Fi 状态。

## 8. 体验 AI 对讲

AI 对讲用于验证设备端麦克风上行、云端 AI 回复、字幕下发和扬声器播放。

1. 确认设备已经连接 Wi-Fi。
2. 在主页向左滑动到第二页，点击 AI 对讲。
3. 等待页面显示正在连接 AI 服务，连接成功后进入会话状态。
4. 连接成功后保持常听，直接对设备说话即可。
5. AI 回复时按下侧键可以打断当前回复。
6. 会话断开后，可以点击“开始新对话”或按侧键重新连接。
7. 页面会展示识别和回复字幕。
8. 点击返回退出 AI 对讲，设备会停止会话并释放音频和 RTC 资源。

如果出现连接异常，请先确认 Wi-Fi 可用，再检查设备是否已经绑定、ThingConnect 在线状态和 AI Chat 授权关系。

## 9. 系统设置和测试

系统设置页包含几个常用入口：

- Wi-Fi 设置：扫描、连接和保存 Wi-Fi。
- 网络测试：验证设备网络连通性。
- TiRTC 配置：查看绑定状态、重置绑定，并保留开发调试字段。
- TiRTC 测试：手动启动或断开 RTC，验证基础连接。
- 关于 / OTA：查看版本信息和执行 OTA 相关操作。

建议首次体验顺序为：连接 Wi-Fi -> 6 位验证码绑定 -> 查看 IP 和设备 ID -> Web 端 IPC -> 网络测试 -> TiRTC 测试 -> 呼叫或 AI 对讲。

OTA 使用路径：主页 -> 设置 -> 关于 / OTA -> 检查更新。下载和校验完成后，页面显示待重启时点击重启生效。详细规则见 [烧录与 OTA 快速教程](FLASH_AND_OTA_CN.md)。

## 10. 常见现象

| 现象 | 处理方式 |
| --- | --- |
| 扫描不到 Wi-Fi | 确认路由器开启 2.4 GHz；点击刷新重新扫描；靠近路由器再试 |
| 密码错误 | 返回连接页面重新输入密码 |
| 连接超时 | 检查 SSID、密码和信号强度，必要时重启路由器或设备 |
| 呼叫提示请先连接 Wi-Fi | 先完成 Wi-Fi 连接并确认查看页能看到 IP |
| Web 端 IPC 连接失败 | 确认设备已连接 Wi-Fi、已绑定并停留在查看页面 |
| AI 对讲连接异常 | 检查网络、设备身份、ThingConnect 绑定状态和 AI Chat 授权 |
| 对端听不到本机声音 | 检查发送音量是否为 0，确认麦克风未静音 |

## 11. 开发者配置位置

发布代码里的 `main/application/app_config.h` 不内置默认 Wi-Fi、设备 ID、设备密钥或远端设备 ID。普通体验通过 6 位验证码绑定获取设备身份；调试私有设备时，可以通过绑定流程、私有后台下发或自己的编译期覆盖配置写入真实信息。

运行中通过绑定流程写入的设备身份会保存在 NVS 中，优先级高于编译期默认值。需要换账号或换环境时，进入设置 -> TiRTC 配置 -> 重置绑定。

AI 对讲使用设备绑定后保存的身份向 ThingConnect 换取短期业务凭证，不在固件中保存 AI Chat 服务端级密钥。
