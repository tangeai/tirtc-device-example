# Changelog

## 0.8.1

- 将 MJPEG 的关键帧请求处理改为无副作用空操作；网页请求 I 帧时不再唤醒媒体/控制线程、重置状态或打断发送节拍。
- 增加静态门禁，确保 TiRTC 回调继续注册，同时禁止关键帧事件链重新进入 MJPEG 例程。

## 0.8.0

- 将演示素材替换为 VOA Learning English 播报员正面出镜的人声片段，连续讲完完整句子，便于检查口型、字幕和声音同步。
- 演示规格调整为 `1280x720 / 15 fps / MJPEG + 8 kHz mono PCMA`，时长增加到 9.4 秒。
- 音频使用响度归一化后再编码为 G.711 A-law，保持网页端已验证的 160 字节、20 ms 分包契约。
- 新增 8 MiB 固件分区的 80% 体积硬门禁，并在构建审计中记录实际占用、上限和余量。

## 0.7.0

- 将演示素材替换为小鸟鸣叫、张嘴和振翅动作清晰对应的音画同步片段。
- 视频升级为 `960x540 / 15 fps / MJPEG`，在提高分辨率的同时降低发送帧率。
- 音频继续使用网页端稳定支持的 `8 kHz / mono / PCMA`，每包 `160 bytes / 20 ms`。
- 转码门禁新增双流零起点、4 秒等长、60 帧和 32000 音频采样检查。

## 0.6.1

- 清理完整 G32S10X 构建中的 177 条编译器/链接器警告，并新增零警告交付门禁。
- 修复时钟父节点参数、`mstatus` 位域宽度、异常前空任务访问、栈回溯指令判断和符号表边界声明。
- 修正 MMC 类型、PLIC 锁限定符、mbedTLS `socklen_t`、系统调用和异常诊断中的类型问题。
- 君正 r1.0.5 的旧诊断格式差异仅在供应商兼容层处理；应用源码继续使用 `-Wformat=2 -Werror`。

## 0.6.0

- 将错误解释独立为诊断层，将 AVI 校验/游标独立为无 RTOS 依赖的纯解析层。
- SDK 回调不再直接打印串口；命令、订阅和关键帧通过固定大小事件队列交给 worker 处理。
- 把线程栈、重试、超时、日志周期、背压阈值和音频包时长集中到用户配置面，并增加编译期范围检查。
- 新增主机 AVI 解析/循环时间戳测试，构建前先验证素材边界和 4 秒循环。
- 重写架构、配置、移植和代码阅读说明，明确每层职责与真机验收边界。

## 0.5.0

- 串口日志统一为 `STEP/PASS/WAIT/FAIL` 测试格式，按联网、校时、上线、连接、订阅和首帧展示结果。
- 健康摘要由 5 秒降为 30 秒，并移除连接指针、凭据长度、媒体目标代数等底层噪声。
- 所有 TiRTC 本地错误码和例程平台错误码都输出中文含义与处理建议。
- 增加视频首帧、音频首包和网页订阅的可验证日志。

## 0.4.0

- 将预录音频从 16 kHz PCM 改为网页 SDK 稳定支持的 8 kHz PCMA/A-law。
- 音频发送改为与 P4 示例一致的 160 字节、20 ms 固定分包，stream ID 仍为 10。
- 对原片低音量片段增加 20 dB 固定增益，避免正确解码后仍只听到底噪。
- 保持 `800x450 / 24 fps` MJPEG 视频不变，素材体积降至 1,728,738 字节。

## 0.3.0

- 将演示素材升级为 `800x450 / 24 fps` 的大屏自然景观片段。
- 视频码率提升到约 3.39 Mbps，总音视频码率约 3.65 Mbps，素材仍小于 2 MiB。
- 视频时间戳改为按 24 fps 有理节拍计算，避免整数毫秒周期造成循环音画漂移。
- 明确设备端为只输出示例，入站音视频数据不接收、不播放。

## 0.2.0

- 增加小于 2 MiB 的 8 秒 MJPEG + PCM 预录演示片段。
- 对端连接后自动循环发送视频和音频，并处理订阅、取消订阅和关键帧请求。
- 媒体文件直接映射到固件只读区，运行时不加载整片、不初始化音视频硬件。
- 增加发送缓冲限流、媒体计数日志、素材授权和构建产物校验。

## 0.1.0

- 从未修改的 Ingenic `im_sdk_v0.4.0` 建立独立示例。
- 集成 TiRTC 2.2.0 G32 RISC-V 静态库。
- 仅保留 FreeRTOS、ATBM WiFi、lwIP/NTP 和 TiRTC 控制面。
- 移除 UI、文件系统业务、OTA 和全部音视频硬件/媒体代码。
